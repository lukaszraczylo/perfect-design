# Contract enforcement brief (shared by all agents)

Repo: <repo root> (pnpm workspace; library packages/ui; run commands from packages/ui with `./node_modules/.bin/vitest ...` / `pnpm exec ...`, never `npm`). READ FIRST: AGENTS.md, DESIGN.md, LLMSlop.md, packages/ui/src/lib/contract.ts (+ contract.test.ts), packages/ui/src/components/overlays/{Dialog,AlertDialog,Sheet} (reference implementation: *Content.vue, *Title.vue) and overlays/contract.test.ts, packages/ui/src/__tests__/{strict-examples,requires-tested}.test.ts, packages/ui/src/docs-types.ts (`requires`).

## Goal (from the user)
"For items REQUIRING something, like Dialog requiring DialogTitle, we should throw an error if those are not provided. There are plenty more." Every component whose docs, a11y notes or common sense say something is REQUIRED must enforce it: a missing required part, prop, name or wiring throws a `ContractError` instead of shipping a broken or inaccessible control.

## The mechanism (already built, do not change lib/contract.ts; if you need a new helper, add it in your own folder or ask by reporting)
- `violation(component, rule, message)`: throws `ContractError` in 'throw' mode (default), `console.error` in 'warn', nothing in 'off'. Message style: `requires X (or set Y).` + a hint saying how to fix, e.g. `Wrap it in VisuallyHidden if it must not be visible.`
- Compound parent/child: owner calls `useRequiredParts('Owner', [{ part: 'PartName', orAttrs: ['aria-label','aria-labelledby'], hint }], useAttrs())` and renders `<RequiredPartsProbe owner="Owner" />` INSIDE the content that exists only when the owner is really shown (a closed dialog must not be checked); the part calls `useRegisterPart('Owner', 'PartName')`. See Dialog.
- Props: `requireText(component, 'label', props.label, hint)`, `requireOneOf(component, { label: props.label, 'aria-label': attrs['aria-label'] }, hint)`. Call them from an async `onMounted` (Vue routes errors from lifecycle hooks to errorHandler; in dev Vue re-throws them). NEVER throw during setup or render (that would blank a live page in production); checks belong in `onMounted` (after `await nextTick()` when headless-lib content renders a tick later).
- Accessible name: `useRequireAccessibleName('Component', () => elRef.value, hint, when?)` (aria-label, aria-labelledby, `<label for>`, visible text, alt). Use `when` to skip legitimate cases (e.g. a named wrapper).
- Structure/wiring checks (e.g. every TabsTrigger value has a TabsContent, RadioCard inside RadioCardGroup, Lightbox controlled `open`, form with no `@subscribe` handler) use the same primitives (`violation` from an async onMounted, parent registry, `getCurrentInstance().vnode.props` for listeners).
- Unit tests of components run with strict mode OFF by default (vitest.setup.ts), so existing tests that mount partial trees keep passing. Contract tests turn it on: `beforeEach(() => configureStrictMode('throw'))`, `afterEach(() => configureStrictMode('off'))`, capture with a wrapper using `onErrorCaptured` (pattern in overlays/contract.test.ts and lib/contract.test.ts, including the `settle()` helper that awaits ticks).

## What to enforce (decide per component; do NOT over-enforce)
Enforce things that make the component broken or inaccessible without them, where a legitimate alternative always exists and is accepted: required parts of compound components; required props that are meaningless when blank (labels, titles, names, values, ids); accessible names for every control (icon-only buttons/toggles/links, inputs without a visible label, groups, regions, trees, tables via caption/label, sliders, ratings, pickers); alt text where an image conveys content (an explicitly empty alt marks it decorative and is allowed); parent/child pairing and uniqueness (tab values, accordion values, command item values, board card ids, radio/checkbox card values); silent no-ops that hide mistakes (an `Icon` with malformed data, social links without a label that are currently skipped, a RadioCard outside its group that is "inert", a newsletter/contact form with no submit handler); controlled-only props (Lightbox `open`). Accept every legitimate way to satisfy a rule (Field label, `aria-label`, `aria-labelledby`, visually hidden text, wrapping `<label>`). Start from the docs' own words: grep the component's docs for ALWAYS / MUST / required / needs / never, then add what an engineer or LLM could plausibly forget.
Internal use counts: library components that render other library components must satisfy those contracts themselves (e.g. a dialog built from DialogContent supplies a title). `src/__tests__/strict-examples.test.ts` mounts every docs example in strict mode and must stay green: fix the example (preferred: examples must model correct usage) or the component, never weaken a rule.

## Deliverables per component you touch
1. Enforcement in the component (messages name the component, the missing thing, and the fix).
2. Tests in your group: `<Name>/<Name>.contract.test.ts` or one `contract.test.ts` at the group folder; for EVERY rule: throws when missing (assert message), passes with each accepted alternative, does not throw in 'off', logs without throwing in 'warn' (one test per component is enough for the modes), no false positive for the normal documented usage. Coverage of your folders stays >=95%.
3. Docs: add `requires: [ '...' ]` to the component's `*.docs.ts` (one sentence per enforced rule, starting "Throws a ContractError when ..."), and keep the existing docs accurate (`src/__tests__/docs-contract.test.ts`, `requires-tested.test.ts` must pass: a documented requirement needs a test in the component folder or `<group>/contract.test.ts` that contains `configureStrictMode` and asserts the error).
4. Everything green: your folders' tests, `./node_modules/.bin/vitest run src/__tests__` (strict-examples, structure, axe, css-validity, docs-contract, requires-tested, slop, contrast, dependencies), `pnpm exec vue-tsc --noEmit 2>&1 | grep components/<yourgroup>` empty.
