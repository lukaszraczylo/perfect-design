Repo: <repo root> (pnpm workspace; library packages/ui; run commands from packages/ui with `./node_modules/.bin/vitest ...` / `pnpm exec ...`, never `npm`). ## Goal (from the user)
"Components should have more variations as the design system is currently heavily limited. Of course everything completely tested." 96 of 173 components currently have at most one variation dimension (often just `size`). A design system that cannot express a filled input, a pill tab set, a compact table, a stepper without numbers or a donut with a thickness is too limited to replace real sites. Add real, useful variations, not decoration.

## What "a variation" means here
A documented, typed prop that changes the look or layout (not behaviour): `variant`, `size`, `tone`, `appearance`, `layout`, `density`, `shape`, `orientation`, `rounded`, `gap`, `columns` (the generic matrix test in src/__tests__/variants-matrix.test.ts discovers props by these names; use them. If a dimension truly needs another name, use it and tell me in your report so the matrix can learn it). Implement with the in-house `cva` (lib/cva) exported next to the component as `xVariants` so plain elements can reuse them. Defaults MUST keep today's output (tests pin it; do not change default class strings). Unknown values fall back to the default. Every new value is in the docs props table with its type, has its own live example (or a clearly labelled gallery example showing all values side by side), and its own tests.

## Quality rules (same as always, enforced by tests)
- LLMSlop.md: no gradients, glows, glass/backdrop-blur, coloured shadows, edge stripes, hover lift/scale, emoji, tracked all-caps, `rounded-2xl`+, arbitrary values, em dashes, buzzwords, invented content. Tokens only. Reuse `focusRing`, `fieldSurface` fragments.
- Colour: new tone/appearance combinations must use token pairs that `src/__tests__/contrast.test.ts` already covers (text on tinted success/info/destructive/primary, foreground on solid status colours, muted-foreground on background/card/muted). Do not invent new pairings; if you need one, say so in your report.
- Accessibility (AUDIT-BRIEF): state never by colour alone (status variants carry an icon or text), 24px targets (44px coarse), 16px form text on small screens, logical properties, forced-colors fallbacks (borders/outlines), reduced motion, reflow at 320px. Required parts stay enforced (CONTRACT-BRIEF): new sub-parts that are required register with the contract helpers; docs examples run in strict mode.
- Minimal dependencies (vue, reka-ui, tailwind-merge, pinia). New helper components go in your own folders and export from the group barrel with a single atomic `echo >>`.
- Do not edit shared files: src/index.ts, src/lib/*, src/styles/*, src/stores/*, vite.config.ts, vitest.setup.ts, scripts/*, docs/src/**, or the shared tests in src/__tests__ (except you may NOT weaken them). Other agents edit other groups concurrently.

## Tests (every variation, "completely tested")
For each component you extend, in its own `*.test.ts` (extend the existing file or add `<Name>.variants.test.ts`): per new value, the expected class/attr/markup (not just "renders"); default output unchanged (assert the exact default class string or a stable subset); unknown value falls back; `class` prop wins over variant classes; combinations of two dimensions do not conflict (a representative cross-product); a11y expectations that depend on the variant (names, roles, icon + text for status, focusable regions); responsive/forced-colors/logical-property classes present; edge cases (empty slots, long text). The generic matrix (src/__tests__/variants-matrix.test.ts), docs-contract, strict-examples, axe, css-validity, slop, contrast, structure and requires-tested tests must stay green. Coverage of your folders >=95%.
