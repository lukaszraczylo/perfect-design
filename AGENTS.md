# Perfect Design: guide for LLMs and contributors

Stack: **Vue 3.5 (script setup, TypeScript) · Vite · Tailwind CSS v4 · Pinia · FontAwesome icon data · Vitest**. Runtime dependencies of the library are ONLY `reka-ui` and `tailwind-merge` (+ optional `pinia`), enforced by `src/__tests__/dependencies.test.ts`.
Library: `packages/ui` (`@perfect-design/ui`). Docs website: `docs/`. Machine-readable: `llms.txt`, `llms-full.txt`, `components.manifest.json` (generated by `pnpm generate:llms`).

## Read first: DESIGN.md and LLMSlop.md

- `DESIGN.md` is the written direction (colours, type, radius, the one characteristic element, allowed content). Change a token there first.
- `LLMSlop.md` lists the patterns that mark UI as LLM-generated, with severities (P0 to P2). Read it before writing or restyling any component, docs example or copy. Run its section 12 self-check before calling UI work done.
- `packages/ui/src/__tests__/slop.test.ts` enforces the mechanical rules over every component and docs file. A hit needs a documented exception in `DESIGN.md` section 7, not a looser pattern.
- Defaults a component ships must already pass: no gradients, glass, glows, tracked all-caps eyebrows, hover lift, stock button labels ("Get started", "Learn more"), buzzwords, emoji, invented people, companies, quotes or metrics in examples.

## Using the library in an app

```css
/* main.css */
@import "tailwindcss";
@import "@perfect-design/ui/theme.css";
@import "@perfect-design/ui/themes/emerald.css"; /* optional accent presets */
@source "../node_modules/@perfect-design/ui/src"; /* REQUIRED so Tailwind sees the component classes */
```
```ts
import { createPinia } from 'pinia'   // only needed for useThemeStore / Toaster / ConfirmHost
import { Button, Dialog, useThemeStore } from '@perfect-design/ui'
```
Token names follow shadcn/ui (`bg-background text-foreground bg-primary text-primary-foreground border-border ring-ring ...`) plus `success|warning|info` (+`-foreground`), `scrim`, `chart-1..5`, `sidebar-*`. Dark mode = `class="dark"` on `<html>`; accent preset = `data-theme="emerald"`. **Never hard-code colours. Use only semantic tokens.**

Style packs (`data-style="workbench|tactile|editorial|raw|contrast|terminal"`, `quiet` = core) change density, corners, depth and type for the whole app or a region (`StyleScope`, `StylePicker`, `useThemeStore().setStyle()`): import `@perfect-design/ui/packs.css`. Choose one pack per product from its brief (DESIGN.md section 8); never imitate a pack with inline colours or shadows.

## The universal customisation contract (every component)

1. **`class` prop wins.** Final class is `cn(internalClasses, props.class)` (tailwind-merge), so consumers can override anything.
2. **`variant` / `size`** are variants (in-house `cva` in `lib/cva.ts`, same API as class-variance-authority) exported next to the component (`buttonVariants`) so non-component elements can reuse the styling (`<a :class="buttonVariants({variant:'outline'})">`).
3. **`as` / `asChild`** (reka-ui `Primitive`) wherever the element type is a reasonable consumer choice.
4. **Every root element has `data-slot="<kebab-name>"`** (and every sub-part `data-slot="<kebab-name>-<part>"`). They are stable hooks for CSS/tests (`[data-slot=card-header]`).
5. **Attributes fall through** (`aria-*`, `data-*`, `id`, listeners). If the root is not the element that should receive them, set `defineOptions({ inheritAttrs: false })` and bind `v-bind="$attrs"` deliberately.
6. **Slots over config props** for content; props for behaviour/appearance. Prefer compound parts (`Card`, `CardHeader`, `CardContent`) for composite UIs.
7. **v-model** via `modelValue` / `update:modelValue` (or reka's `v-model:open` style when wrapping reka). Support controlled AND uncontrolled use.
8. **Accessibility is built in**: roles, labels, keyboard, focus ring (`focusRing` from `lib/styles`), `aria-invalid`, `aria-busy`, reduced-motion safe.
9. **Tokens only.** Shared class fragments live in `src/lib/styles.ts` (`focusRing`, `invalidRing`, `fieldSurface`, `floatingSurface`, `touchTarget`).
10. **Icons**: FontAwesome-shaped `IconDefinition` data passed to `<Icon :icon="faCheck" />`, rendered as inline SVG (no FontAwesome runtime). Library code imports icons from `lib/icons` (regenerate with `pnpm tsx scripts/gen-icons.ts`).
11. **Dependencies are a budget.** Source files may import only `vue`, `reka-ui`, `tailwind-merge`, `pinia` and relative paths. Use `lib/cva`, `lib/cn`, `lib/use-helpers` (debounce, clipboard, online, scroll) instead of clsx/CVA/vueuse. Component SFCs have no `<style>` blocks (shared keyframes live in `styles/theme.css`).

## Required parts are enforced

What a component documents as required is enforced with a `ContractError` (`packages/ui/src/lib/contract.ts`): a `DialogTitle` inside `DialogContent`, a label on an icon-only button, an `alt` on an informative image, a submit handler on a form. When you add a component, list its requirements in `requires` in the docs file and enforce each with `useRequiredParts`/`RequiredPartsProbe`, `requireText`, `requireOneOf` or `useRequireAccessibleName` from an async `onMounted` (never during setup or render). Every documented requirement needs a test that sets `configureStrictMode('throw')` and asserts the error (`src/__tests__/requires-tested.test.ts`). `src/__tests__/strict-examples.test.ts` mounts every docs example in strict mode, so examples must model correct usage. Unit tests run with strict mode off by default (`vitest.setup.ts`); contract tests turn it on. Apps choose `'throw'` (default), `'warn'` or `'off'` with `configureStrictMode`.

## Folder & file contract (enforced by `src/__tests__/structure.test.ts`)

```
packages/ui/src/components/<group>/<Name>/
  <Name>.vue            implementation (<script setup lang="ts">)
  [variants.ts]         CVA definition(s), exported via index.ts
  [<Name><Part>.vue]    compound parts
  <Name>.test.ts        tests: good path, customisation, bad path, edge cases
  <Name>.docs.ts        default export ComponentDoc (see src/docs-types.ts)
  index.ts              barrel: `export { default as X } from './X.vue'` + types + variants
components/<group>/index.ts   re-exports each folder
```
Groups: `primitives · typography · layout · forms · feedback · overlays · navigation · data-display · marketing`.

Reference implementations (copy their shape): `primitives/Button` (CVA + Primitive), `primitives/Badge`, `forms/Input` (v-model), `overlays/Dialog` (reka compound + portal tests).

## Tests (Vitest + @vue/test-utils, jsdom)

Cover: **good path** (renders, variants, v-model, emits, slots) · **customisation** (class merge/override, attrs passthrough, `as`/`asChild`) · **bad path** (invalid props fall back, disabled/readonly/loading block interaction, empty/null input, rejected values) · **edge cases** (empty slots, huge/unicode/RTL text, rapid toggles, boundary numbers, unmount cleanup of timers/listeners). Coverage threshold is enforced (95/90/95/95).
Notes: `wrapper.setValue()` on a component root EMITS directly; use `wrapper.find('input').setValue()` to exercise the DOM. Portalled content: `mount(..., { attachTo: document.body })` and query `document.body`; clean up in `afterEach`. Use `vi.useFakeTimers()` for timing.

## Docs (every component)

`<Name>.docs.ts` → ComponentDoc: summary, description (when to use / not use), props table (complete and accurate), slots, emits, ≥2 `examples` (minimal + realistic; template snippets that mount warning-free with all components globally registered; use `state()` + display `script` for reactive demos), a11y notes, related, `llmNotes` (terse imperative rules), `replaces` (existing app components this supersedes). The structure test mounts every example.

## Commands
`pnpm test` · `pnpm test:coverage` · `pnpm typecheck` · `pnpm generate:llms` · `pnpm dev` (docs site) · `pnpm build`.

## Do / Don't (for LLMs generating UI with this library)
- DO import from `@perfect-design/ui`; DO use semantic tokens; DO put one `variant="default"` button per view.
- DO wrap forms fields in `Field` (label + hint + error wiring).
- DON'T hard-code hex/rgb/oklch colours, DON'T use `style` for spacing, DON'T re-implement a component that exists here.
- DON'T mutate props; use `v-model`.
- DON'T copy the stock page: centred hero, pill badge, two buttons, logo row, three identical icon cards, pricing, CTA band (LLMSlop L1 to L3). Lead with the product; give the important feature more room.
- DON'T write a default `title`, `description`, button label or sample content that fits any product. Name the action ("Open the catalogue") and the thing. Sample data is labelled as sample.
- DON'T name the owner's real projects or companies anywhere (docs, examples, tests, `replaces`). Invent fictional company names when an example needs one.
- DON'T add an animation that marks no state change. Reveal, count-up and hover lift are off by default.

## Accessibility, performance and audit tooling

The standard is WCAG 2.2 AA, a responsive layout that reflows at 320px, Lighthouse 100 in all four categories, and the Chrome Modern Web Guidance (`reports/guidance/*.md` holds the guides used; `npx modern-web-guidance legacy-scan` must report 0 findings).

| Check | Command | What it enforces |
|---|---|---|
| Colour contrast for every theme | `pnpm test` (`src/__tests__/contrast.test.ts`) | Text 4.5:1, tinted status text 4.7:1, control borders and focus ring 3:1, light and dark, every accent preset |
| Real-browser axe + overflow sweep | `node scripts/a11y-sweep.mjs <url> [--match /components/forms/ \| --routes /,/guides/llm] [--style workbench] [--out file]` | axe WCAG 2.0/2.1/2.2 A+AA + best-practice at 320/768/1280px, light and dark, every live demo mounted (`?eager`), horizontal overflow, console warnings |
| Lighthouse | `node scripts/lighthouse.mjs <url> [paths...]` | Performance, accessibility, best practices, SEO and Agentic Browsing (llms.txt, ARD manifest) on mobile and desktop |
| Agent discovery files | `pnpm generate:llms` then `pnpm --filter docs test` | `llms.txt` (H1, links, every component) and `/.well-known/ard.json` validated with Lighthouse's own ARD conformance code |
| Browser behaviour tests | `node scripts/browser/behaviour.mjs <url> [--match substr]` (also run by `pnpm test:browser`, not in CI) | Real pointers, focus and layout: Tooltip opens on hover/focus and closes on leave/Escape; Popover, HoverCard and DropdownMenu stay inside the viewport at 320 and 1280px near every edge; Accordion, FAQ and Tabs focus order, roving and focus ring; Dialog focus trap, Escape and focus return; Sheet and Select scroll lock; Slider and ResizablePanels pointer, keyboard and RTL; Combobox typeahead and keyboard selection; Toast close button, Escape and focus return; ThemeToggle, StylePicker and AccentPicker set `<html>` attributes and persist across a reload; Button targets are at least 24px in every style pack. Every test also runs against a sabotaged page and must fail there |
| Browser state check | `node scripts/state-check.mjs <url>` | Controls toggle, the state is visible, and focus is visible, in light and dark |
| Slop guard | `pnpm test` (`src/__tests__/slop.test.ts`) | The mechanical rules of `LLMSlop.md` |
| Static docs build | `pnpm --filter docs build` then `pnpm --filter docs preview` | Server-renders every route to HTML (hydrated in the browser), serves like a static host |

Component rules that follow from this: focus ring via `focusRing` (also visible in forced-colors mode), 24px minimum targets (`pointer-coarse:` raises primary controls to 44px), 16px form text on small screens, logical properties (`ms-`/`pe-`/`start-`) so right-to-left works, scrollable regions are focusable and named, status changes go through one polite `role=status` region, motion respects `prefers-reduced-motion`, and state never relies on colour alone.
